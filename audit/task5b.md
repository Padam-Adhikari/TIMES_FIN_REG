Data layout in `VT_FINTIMES_TRA` (new cases for the tool):
- Existing stock trajectories (`Stock~2010` ... per vehicle subclass, 33 processes) are in a table whose
  region is in the tag (`000Veh`!F120 `~FI_T: FI`); one more uses `~FI_T: Region=FI` (F160). As for cement
  (4c), these are disabled in Reg mode and copied per region - here to all 19 regions with stock x key.
- Some tables use region-year headers (`kmPerVeh`!F118 `AF~LO` with `FI~2010`, `FI~2011`, ...): the copy
  must map every `FI~<year>` column, not only `FI`.
- The other attribute tables (`ACTFLO`, `EFF`, `AF`, `Rail`) have an `FI` column (4b copy mechanism).
- `FuelTech` is generic (no region column): applies wherever the processes are declared (confirmed in 5a).

Demand: `COM_PROJ` comes from `Scen_ZUDemand_REF2016` (included last, wins) and `Scen_ZATEMP_Calibration`
(2015 values for cars, trucks, buses, vans, two-wheelers). In Reg mode the ZUDemand rows on the hub are
commented out and split on `Reg_Demand`; **the calibration rows of the moved demands must be commented out
too**, otherwise the hub would get the calibration value back in 2015 on top of the regional demand.

## 8. First VEDA sync (2026-11-18): duplicate column -> fixed (`--step 5bfix`)

The sync stopped: "Veda-Tag table(s) has duplicate column names" in `Scen_TRA_SCENARIOS` (`~UC_T: UC_NCAP~LO`).
The diesel-car tables (`Transport UC` rows 4 and 15) have both an `AllRegions` column (0.46) and an `FI`
column (0.9, the Finnish coefficients); `plan_ucs_general` switched `FI` to `AllRegions` without looking at the
existing column. Fix: the old column is `*AllRegions` (comment) in Reg mode, so the FI coefficients - the
effective single-mode values for Finland - apply in the national constraint; `plan_ucs_general` now does
this whenever both columns exist. New pre-sync check `tools/reg_header_scan.py`: every VEDA table header as
seen in Reg mode, duplicates reported. Whole model: only these two tables (two hits in the untouched
`SubRES_22` are plain constants identical in both modes, accepted by VEDA in every sync so far).
